# Agent-DLC Workshop site

This is a static React website for the bilingual (中文 / English) **Agent-DLC with AgentCore Launchpad** workshop. The workshop is written for AWS Workshop Studio. The site turns that Markdown into one page per chapter, so the content can be published on GitHub Pages.

- Routes: `/<lang>/`, `/<lang>/10-prepare`, `/<lang>/20-flywheel/30-evaluate`, …, where `lang` is `zh` (the default) or `en`.
- Every page has a persistent table of contents: a sidebar on desktop and a drawer on mobile. It also has an outline of the h2/h3 headings on the page and links to the previous and next chapter. The language switch keeps you on the same page.
- These Workshop Studio constructs are rendered:
  - `::alert[…]{type=…}`
  - `:::expand{header=…}` (rendered as `<details>`)
  - `:link[…]{href=":assetUrl{…}" action=download}`
  - GitHub tables, fenced code with a copy button, and Mermaid diagrams
  - Absolute internal links such as `](/20-flywheel/30-evaluate)`
  - `/static/...` images

  HTML comments are dropped.

Live site: <https://yourlin.github.io/agent-dlc-workshop/>

## Layout

```
scripts/sync-content.mjs   content pipeline (remark/rehype + Workshop Studio directive transform)
scripts/postbuild.mjs      emits 404.html, one index.html per route (pre-rendered), .nojekyll
scripts/serve_dist.py      local static server that behaves like GitHub Pages (404.html fallback)
tests/e2e_check.py         Playwright smoke test (TOC, images, directives, deep links, mobile)
src/                       React app (Vite + TypeScript + react-router)
src/generated/             GENERATED by `npm run sync` – committed
public/static, public/assets   GENERATED by `npm run sync` (copied images, templates, downloads) – committed
.github/workflows/pages.yml    build + deploy to GitHub Pages
```

## Update the content (`npm run sync`)

```bash
npm ci
# The source repo defaults to ../agent-dlc-ws-remote
npm run sync
# or point it somewhere else
WS_CONTENT_DIR=/path/to/agent-dlc-ws-remote npm run sync
```

`sync` does the following:

1. Reads `content/**/index.{zh,en}.md` and `NN-slug.{zh,en}.md`, and orders pages by the frontmatter `weight`. New groups such as `90-appendix/` are picked up automatically.
2. Writes the rendered HTML and heading outline of each page to `src/generated/pages/<lang>/<route>/index.json`, and the page tree to `src/generated/nav.json`.
3. Copies the source repo's `static/` folder to `public/static/` and its `assets/` folder to `public/assets/`.
4. Rewrites `/static/...` and `:assetUrl{path=...}` links to point at those copies.

URLs are stored with a `%BASE%` placeholder, so the committed output works with any base path.

At the end, `sync` prints warnings for:

- links to pages that don't exist yet
- missing image or asset files
- unsupported directives
- directive syntax that didn't parse
- raw HTML that was shown as text, such as `<username>`
- pages that exist in only one language

After syncing, review the diff and commit `src/generated/` and `public/`.

## Local development and preview

```bash
npm run dev                         # http://localhost:5173/  (base "/")

npm run build                       # sync + type-check + vite build + postbuild
BASE_PATH=/agent-dlc-workshop/ npm run build:site   # build only, from committed content, with a base
BASE_PATH=/agent-dlc-workshop/ npx vite preview     # http://localhost:4173/agent-dlc-workshop/

# Serve dist/ like GitHub Pages (unknown paths -> 404.html); --spa-only ignores the
# per-route index.html files to exercise the pure SPA fallback.
python3 scripts/serve_dist.py --base /agent-dlc-workshop/ [--spa-only]

# Smoke test (needs Python Playwright + chromium)
python tests/e2e_check.py --url http://127.0.0.1:4173/agent-dlc-workshop/ --shots /tmp/site-shots
```

`BASE_PATH` is the sub-path the site is served from. For a project site, use `/<repo-name>/`. For a user site or a custom domain, use `/`.

## Deploy to GitHub Pages

1. Push this repo to GitHub, with `main` as the default branch.
2. In the repo, go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**.
3. Each push to `main`, or a manual run of the workflow, runs `.github/workflows/pages.yml`. The workflow:
   - runs `npm ci` and then `npm run build:site` with `BASE_PATH` taken from `actions/configure-pages`
   - deploys `dist/` to Pages

The workflow does **not** run `sync`, because the content repo is not available on GitHub. To publish new content, run `npm run sync` locally, commit, and push.

Deep links work without JavaScript routing tricks. Every route has its own `index.html`, which contains pre-rendered content for crawlers and readers without JS. Any other path falls back to `404.html`, which is a copy of the SPA shell.
